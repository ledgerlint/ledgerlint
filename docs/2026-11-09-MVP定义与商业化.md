> 作者：许清楚（产品经理）｜前置文档：`2026-11-09-复盘与重新定位.md`
> 原则：影响力优先、商业其次；MVP 必须能用「只有银行流水 + 发票」的真实数据验证；严禁范围膨胀。

> **⚠️ 口径变更（2026-11-09，主理人确认）**
> 1. **截止日提前**：主理人可协调母校创业中心对接初创学生公司试用，条件是「12 月内完成 MVP」。故 MVP 截止日从「12 周后」改为 **2026-12-31**，原 12 周计划压缩为 **7 周**。本文出现「12 周」的阈值，一律按 7 周口径重读；路线图见 §5。
> 2. **真实数据来源变更**：从「只能拿到部分流水/发票，来源不确定」改为「**母校创业中心 → 初创学生公司**」这一确定渠道。这解除了原 R1 风险，也使 A2 的 L1/L2 双层验证可行。
> 3. **压缩方式只有一种**：砍范围，不砍验收。被砍的功能见 §5.3。

## ① MVP 一句话定义

> **OpenLedger（暂名）是一个 `npx` 一行启动的本地工具：把一家小企业的银行流水与发票，变成一份带机检与局限说明的凭证草稿包，供创始人自查、供会计/代账复核。**

三个限定词，缺一不可：
- **本地**：数据不出本机，纯文本可审计。
- **凭证草稿包**：产出的是「交出去之前要先过一遍」的输入，不是报税依据。
- **带局限说明**：结论随身携带「我没查什么」，这是唯一的信任护城河。

## ② MVP 功能范围

### 2.1 P0（必须做，缺一不可上线）

| # | 功能 | 一句话说明它服务首个 100 用户的哪一步 | 复用来源 |
|---|---|---|---|
| P0-1 | `npx` 启动 + 本地 Web（127.0.0.1 + token） | 让用户 1 分钟装上、不装坏电脑 | BP2 server 模式 |
| P0-2 | 账套初始化（主体 3 字段 + 期初白名单 + A7/A19 断言） | 让存量公司能进来，且期初不能污染利润表 | BP2 opening-* + C4 修法 |
| P0-3 | 银行流水导入（CSV/Excel，≥3 家主流网银 + 通用列映射 + 幂等） | 用户手上唯一确定有的东西 | BP2 `import/` |
| P0-4 | 发票台账导入（Excel/CSV） | 收入/成本与税额的另一半 | BP2 `invoice.ts` + `tax-doc.ts` |
| P0-5 | 流水→凭证草稿规则引擎（≥20 类高频事件；每条给依据 + 人话） | 把「流水」翻译成「会计动作」，这是零知识可用的核心 | BP2 `events.ts` 改造 + `confirm.ts`/`inbound.ts` |
| P0-6 | 三问推导事件（钱动了吗 / 交付了吗 / 开票了吗） | 让用户点的是业务事实，不是会计动作 | 新写（审阅 H1） |
| P0-7 | 流水↔发票勾稽 + 差异清单（未匹配必须显形，不静默丢） | 保证「账实相符」可被检查 | 新写 + `reconcile` 思路 |
| P0-8 | 单一落账入口 + 凭证不可变 + 哈希链（确认/红冲/作废） | 让「可审计」不是口号 | BP2 `voucher.ts`/`chain.ts`/`ledger.ts` |
| P0-9 | 机检 v1：外部对齐 + 跨表勾稽 + 局限输出（BLOCK/WARN） | 让绿勾可被正确解读 | BP2 `assertions.ts` 框架 + A28/A29 修法 |
| P0-10 | 交付包导出（凭证清单 + 科目余额表 + 利润表草稿 + 机检报告 + 局限说明 + 数据说明） | 这是用户拿走的东西，是产品终点 | BP2 `reports.ts`/`filing.ts` 改造 + `export-csv` |
| P0-11 | 数据可带走（export/import 字节级一致 + hash 校验） | 开源信任的兑现：数据是你的 | BP2 快照思路 + 新 journal |
| P0-12 | 反向构造探针库 + CI 门禁（typecheck/测试/一致性/探针） | 防止「断言全绿而账错」复发 | 新写（本 MVP 的验收基建） |

### 2.2 P1（可延后，不阻塞 v0.1）

| # | 功能 | 延后理由 |
|---|---|---|
| P1-1 | PDF/OFD 发票解析 | 先支持 Excel/CSV 台账，覆盖早期用户够用 |
| P1-2 | 更多银行格式（按 issue 驱动） | 不做「预先猜所有格式」 |
| P1-3 | Beancount 风格导出 | 接入 PTA 生态，放大影响力，但不影响核心闭环 |
| P1-4 | 工资 / 研发加计（复用 BP2 core，后置） | 与「流水+发票」切口弱相关；有资产但非首需 |
| P1-5 | 月度/季度提醒时间轴（申报日历） | 价值高、成本低，但排在「能跑通」之后 |
| P1-6 | MCP / 只读 API（二次开发） | 开源可编程接口，V1 再做 |
| P1-7 | LLM 只读解释（BYOK，默认关） | 非必需；铁律约束下才可接 |
| P1-8 | 完整结账 / 年结 | 需完整期末数据才能验证，MVP 不做 |

### 2.3 明确不做（MVP 及 v1 前）

一般纳税人抵扣 · 报税直连 · 发票真伪查验 · 多主体/多用户/权限 · 进销存 · 移动端 · 桌面安装包 · 无人值守全自动 · 替代代账 SaaS · 云同步/账号/订阅计费 · 专利/脱敏/OFD · 集团合并。

## ③ 可度量验收标准（替代「879 测试全绿」）

> 每条都能用「只有流水/发票」的数据验证；每条都有明确测法。**任何一条不达标，不得发布 v0.1。**

| # | 指标 | 定义 | 合格线 | 测法 | 数据来源 |
|---|---|---|---|---|---|
| A1 | **流水覆盖率** | 进入系统的流水条数中，产出草稿（含「待人工判断」）的比例 | ≥98%，未覆盖必须逐条列原因 | 脚本统计：总条数 vs 草稿数 vs 未覆盖清单 | 真实流水 |
| A2 | **分录一致率（分层）** | **L1 报表层**：系统科目余额表 vs 代账同期报表，在「科目 + 期末余额」上一致的比例；**L2 分录层**：抽 50 笔与人工标注答案逐条 diff（科目 + 方向 + 金额全对）的比例 | L1 ≥98%；L2 ≥90%（首轮）/ ≥95%（发布） | L1 直接比对报表；L2 抽样人工标注 | 代账报表（L1）；抽样标注（L2）|
| A3 | **税分离正确率** | 小规模 1%/3% 价税分离正确的比例 | ≥99% | 对每条含税交易核税额 | 流水+发票 |
| A4 | **勾稽差异可解释率** | 系统产出报表与代账同期报表的差异项中，被逐条解释的比例 | 100%（不允许「默认吸收」） | 差异表逐项核对 | 代账报表 |
| A5 | **可解释率** | 草稿能回答「来自哪条流水/发票 + 用了哪条规则 + 为什么这个科目」的比例 | 100% | 抽查 + 字段完整性校验 | 系统输出 |
| A6 | **机检有效性（反向）** | 每条 BLOCK 级断言都有 ≥1 个「本该报」的反例探针，且探针确实触发 | 100% 覆盖 | 探针库 CI 必须全触发 | 探针库 |
| A7 | **零静默失败** | 未识别/未匹配/金额为 0/科目缺失，必须出现在「待处理清单」 | 100%，不允许静默跳过 | 注入异常样本，检查清单 | 构造样本 |
| A8 | **数据可带走** | export 后在新机器 import，凭证/草稿/配置字节级一致 | 100%（hash 相等） | 往返测试 | 自建账套 |
| A9 | **性能** | 1,000 条流水：导入 → 草稿生成 ≤30 秒 | ≤30s（普通笔记本） | 计时脚本 | 构造 1000 条 |
| A10 | **真实数据闭环** | 至少 1 家真实企业的**一个月**流水+发票，走完 P0-1→P0-11 | 通过，且 A1–A9 达标 | 端到端人工跟跑 | 真实企业 |

**为什么这套标准能替代「测试全绿」**：
- 它测的是**对外部事实的符合度**（A2/A3/A4/A10），不是内部一致性；
- 它要求**探针必须能失败**（A6），杜绝 A8 式恒等式；
- 它要求**差异必须解释**（A4），杜绝「未分配利润主动吸收」；
- 它要求**真实数据**（A10），杜绝仿真自证。

**保留的工程门禁**（必要非充分）：typecheck 0 错 · 单测全绿 · 文档-断言数一致性脚本 · 探针库全触发。**这些是地板，不是天花板。**

## ④ 开源发布形态

### 4.1 安装与 5 分钟上手

| 项 | 内容 |
|---|---|
| 安装 | `npx openledger@latest ./mybook`（主路径）；`npm i -g openledger`（次路径） |
| 依赖 | Node ≥20；零原生依赖（避免 node-gyp 安装失败） |
| 5 分钟路径 | ①一条命令 → ②浏览器打开 → ③点「加载示例账套」→ ④看到 20 条待确认草稿 → ⑤点「生成交付包」→ ⑥打开交付包 |
| 示例账套 | **仓库内 fixtures，不依赖外部路径**（修 BP1 X1「688 全绿不可移植」缺陷） |

### 4.2 README 结构（首屏决定转化）

1. 一句话 + 30 秒 gif（流水进 → 凭证包出）
2. 安装（一条命令）
3. 5 分钟教程（含示例账套）
4. **它做什么 / 不做什么（局限前置，不藏在文末）**
5. 数据格式说明（`mybook/` 目录结构 + 哈希链怎么验）
6. 路线图（P0/P1/不做）
7. 贡献方式（如何加一个银行格式 / 一条规则 / 一条断言）
8. 许可证 + 免责声明

### 4.3 许可证建议

| 方案 | 判断 | 理由 |
|---|---|---|
| **AGPL-3.0-or-later（核心）** | ✅ **推荐** | ①防止专有 SaaS 白嫖（影响力优先但不做冤大头）；②自托管与个人使用完全自由，符合技术创始人；③单一许可证，solo 可维护；④双许可留作 W36+ 选项（需 CLA） |
| Apache-2.0 | ❌ | 允许闭源 fork 做 SaaS，与「影响力 + 防白嫖」冲突 |
| BSL | ❌ | 非 OSI 认证，伤害「真开源」叙事 |
| 双许可 | ⏸ 暂不做 | 需 CLA 与法务，solo 阶段成本高 |

**规则包/行业包**：代码 AGPL；行业模板/科目映射等**数据**用 CC BY-SA 4.0 或单独商业许可（W16+ 定）。**边界原则：核心引擎永远开源，行业知识包可作为商业边界。**

### 4.4 贡献机制

| 机制 | 内容 |
|---|---|
| CONTRIBUTING | 三类入口：加银行格式 / 加规则 / 加断言。每类给模板与测试要求 |
| good-first-issue | 预置 20 个（新增一个银行格式、补一个税参数、修一个文案） |
| 合并门槛 | **新增 BLOCK 断言必须自带反向探针**，否则不合并；规则包必须声明 schema 版本 |
| 规则包目录规范 | `rules/<industry>/<version>/`，声明式 YAML，不含可执行代码进核心 |
| 决策记录 | 所有产品决策进 `docs/decisions/`，与代码同仓，可 diff |

### 4.5 规则包插件边界

| 层 | 允许 | 禁止 |
|---|---|---|
| 核心引擎 | 解析 journal、跑断言、生成报表 | 不含任何行业关键词、不 import 规则包 |
| 规则包 | 科目映射、事件模板、税参数、关键词表（声明式） | 不含任意代码执行、不绕过断言 |
| 插件接口 | 稳定 schema 版本 + 版本校验 | 插件不得读写 journal 之外的文件 |

## ⑤ 迭代路线图（压缩版：7 周，2026-11-10 → 2026-12-31）

> 每周必须有**可交付物 + 验收点**；允许裁剪，**不允许「这周在重构」**。
> 7 周 ≈ 280 小时（按 40h/周）。压缩的唯一手段是砍范围（§5.3），验收标准一条不降。

| 周 | 日期 | 主题 | 可交付物 | 验收点 |
|---|---|---|---|---|
| W1 | 11/10–11/16 | 骨架 + 内核迁移 | 仓库 + `mybook/` journal 存储 + 迁移 `money/lines/chain/ledger/voucher` + CI（typecheck/测试） | 能读写 journal；红冲语义测试通过；CI 绿 |
| W2 | 11/17–11/23 | **输入层 + 伙伴落地** | 流水解析（复用 `import/`，先做 2 家银行格式）+ 统一 transaction 模型；**同步完成创业中心 2 家伙伴对接** | 幂等测试通过（同批/换批 0 新增）；**拿到第 1 份真实流水并跑通解析** |
| W3 | 11/24–11/30 | 规则引擎 v1 | 流水→草稿（**≥12 类**事件）+ 三问（**只对 top5 歧义事件问**）+ 一句人话 | 用真实流水跑，A1 流水覆盖率 ≥90%（首轮） |
| W4 | 12/01–12/07 | 确认 UI + 交付包 v0 | 两页 UI（确认 / 交付包）+ 交付包（凭证清单 + 科目余额表 + 利润表草稿 + 局限） | 端到端：导入→草稿→确认→出包 跑通 |
| W5 | 12/08–12/14 | **机检 v1 + 真实回归 #1** | 5 条硬断言 + 银行余额勾稽；第 1 家全月流水比对 | A2-L1 ≥95%（首轮）；A2-L2 ≥85%（首轮）；A4 差异 100% 可解释 |
| W6 | 12/15–12/21 | 修规则 + 真实回归 #2 + 发布物料 | 按第 1 家偏差修规则；第 2 家验证；README + 示例账套 + 30 秒 gif | A1 ≥98%；A2-L1 ≥98%；A2-L2 ≥90%；A6 探针覆盖 5 条 BLOCK |
| W7 | 12/22–12/31 | **v0.1 发布 + 试用启动** | GitHub 公开（AGPL）+ 发布博文；创业中心 3–5 家试用开班 | **A10 达标（≥1 家真实闭环）**；试用 ≥3 家启动 |

### 5.1 里程碑判据（只有两个生死点）

- **W2 是第一个生死点**：拿不到第 1 份真实流水 → 立即启动创业中心备选（校友企业/往届学生公司），**不得先写规则**。
- **W7 是第二个生死点**：A10 不达标 → 按文档一 §9 总失效条件转向，不在 12 月后硬撑。

### 5.2 与创业中心协作的硬约定

| 事项 | 约定 |
|---|---|
| 找谁 | 创业中心推荐的**已注册、有真实流水、小规模纳税人**的学生公司（1–5 人），优先「已被代账敷衍过」的 |
| 要什么 | 近 1–3 个月**银行流水导出 + 销项/进项发票台账 + 代账给的报表**；脱敏（账号打码） |
| 给什么 | 免费使用 + 一份「你这本账哪里可能有问题」的机检报告；不承诺报税正确性 |
| 合规 | 签一页《数据处理说明》，明确数据仅本地处理、不离开其电脑、可随时删除 |
| 时间点 | **W2 前敲定 2 家，W5 前第 1 家跑完** |

### 5.3 为 7 周砍掉的范围（相对原 12 周方案）

| 原计划 | 处置 | 理由 |
|---|---|---|
| 发票台账导入（P0-4） | → P1，W3 起仅支持「CSV 可选导入」 | 无发票也能出包；有则增强勾稽 |
| 发票↔流水勾稽（P0-7） | → 缩为「未匹配清单」 | 不做自动匹配算法，先显形 |
| 机检 27 条 / 探针全量 | → **只做 5 条 BLOCK**（借贷平衡、科目存在、价税分离、银行余额勾稽、利润表↔资产负债表衔接） | 5 条硬断言比 27 条软断言有用 |
| 三页 UI | → 两页（确认 / 交付包） | 导入并入确认页 |
| export/import 字节一致 | → 目录 hash 校验（纯文本天然可拷） | 成本从 3 天降到 2 小时 |
| 多银行格式 | → 2 家（招行/工行），其余等 issue | 不为想象写解析器 |
| Beancount 导出 / MCP / LLM 解释 / 工资 / 研发加计 | → 全部推到 v0.2 之后 | 与 12 月目标无关 |

## ⑥ 商业化方案（影响力优先）

| 方案 | 是否做 | 何时 | 风险 | 与定位关系 |
|---|---|---|---|---|
| **GitHub Sponsors / 爱发电** | ✅ 做 | W9 起 | 收益低，但信号强（证明有人愿意为开源付费） | 影响力直接体现 |
| **付费行业规则包** | ✅ 做（有条件） | W16+ | 与 AGPL 冲突需设计（数据 vs 代码）；过早收费伤口碑 | open-core 边界；影响力与商业的平衡点 |
| **咨询 / 实施 / 培训** | ✅ 做 | W12 后 | 占用开发时间（最大风险） | 现金流；也是真实需求输入源 |
| **托管版 SaaS** | ❌ 不做 | W36+ 评估 | **ICP 许可证**（BP `10 §1`：自建订阅收费站=撞枪口） | 与「本地数据」定位也有张力 |
| **双许可（AGPL + 商业）** | ⏸ 暂不做 | W36+ | 需 CLA/法务；solo 成本高 | 有企业需求再评估 |
| **认证 / 支持合同** | ⏸ 暂不做 | W36+ | 需服务能力 | 远期 |
| **卖断/序列号授权** | ❌ 不做 | — | 与开源免费冲突；BP `10` 的 A 路径是旧定位 | 已过时 |

**商业化纪律**：至 2026-12-31 前**零收费**（即前 7 周）。影响力优先不是口号——**在没有人用之前谈钱，是把仅有的注意力也浪费掉。**

## ⑦ 成功与失败判定信号

### 7.1 成功信号（满足越多越确定）

| # | 信号 | 阈值（2026-12-31 / 6 个月） | 含义 |
|---|---|---|---|
| S1 | 真实数据闭环 | 12/31 前 ≥1 家；6 个月 ≥3 家 | 切口被需要 |
| S2 | 分录一致率 | ≥95% 且差异可解释 | 会计正确性可自证 |
| S3 | GitHub | 12/31 前 300–800 star；6 个月 ≥1,500 | 影响力起步 |
| S4 | 外部贡献 | 12/31 前 ≥3 个外部 PR；6 个月 ≥10 | 社区成立 |
| S5 | 留存 | 6 个月 ≥5 人每周使用 | 不是一次性下载 |
| S6 | 付费意愿 | 6 个月 ≥10 人愿意为规则包/赞助付费 | 商业可行性初现 |

### 7.2 失败 / 转向信号（触发即启动预案）

| # | 信号 | 判定 | 预案 |
|---|---|---|---|
| F1 | **W2 结束仍无第 1 份真实流水**（创业中心渠道未落地） | **渠道不通，不是切口错** | 立刻换备选（校友企业/往届学生公司/本地代账工作室），再给 2 周；W4 仍无 → 触发总失效条件 |
| F2 | 真实回归分录一致率 <80% 且规则难提升 | **规则/切口错** | 缩到更窄任务（只做「收入成本归集」或「发票↔流水勾稽」），不扩功能 |
| F3 | A4 差异无法解释（大量「默认吸收」） | **会计正确性无法自证** | 停止宣称「机检」，退回「流水整理工具」定位 |
| F4 | 6 个月 star <100 且无复访 | **影响力路径不成立** | 接受「小而稳的自用工具」，放弃「有影响力的开源项目」目标，或转为纯商业咨询 |
| F5 | 范围膨胀复发（新增模块 > 入口层投入） | **第四次同一种坑** | 触发门禁 6.5，冻结新功能 2 周，强制删代码 |
| F6 | 连续 2 周无可交付物 / 主理人 burnout | **节奏失败** | 裁剪路线，保 W9 发布；宁可少功能不可断更 |

### 7.3 一句话决策规则

> **以「1 家真实企业的 1 个月真实流水+发票，走完一个可解释的凭证包」为唯一北极星。** 达成它之前，任何新功能都是负债；达成它之后，任何扩张都要过 6.5 门禁。
