## 为什么是 ledgerlint

1. **`lint` 精确对应产品本体**。lint = 不改动原文、只按规则扫一遍并给出可解释的告警。这正是「机检」在做的事（5 条 BLOCK 断言 + 局限说明），比 `check` 更准确。
2. **对目标客群零解释成本**。客群是技术型创始人，`npx ledgerlint ./mybook` 一眼看懂。
3. **顺手划清边界**。lint 不替你写代码，产品不替你记账——这条边界是前两版反复越过的。
4. **命名空间干净**。npm 与 GitHub 组织双可用，品牌、包名、组织名三者一致，无后缀妥协。

## 为什么否决 `bookcheck`（原始提议）

主理人最初倾向 `bookcheck`（布契）。技术侧确实可用（npm/GitHub 均 404），但**品牌侧不可用**：

| 事实 | 证据 |
|---|---|
| 存在同名同行业公司 | **BookCheck**，英国 Gloucestershire，1994 年成立，60–70 人，9 名注册会计师 |
| 业务高度重叠 | 外包记账 + 管理报表 + 工资 |
| 服务形态撞车 | 招牌服务是「30 项检查清单，**红/黄/绿**三色」——与 BP2 的 OK/WARN/BLOCK 同构 |
| 域名 | `bookcheck.co.uk` 为其所有，`.com` 亦在其手 |

**结论**：npm 空闲只说明没人发过包，不代表品牌可用。对「影响力优先」的项目，搜索流量被同行业公司截走是致命的；且一旦产生商业收入，对方在同一领域的在先使用权几乎必然被主张。

**并否决中文名「布契」**：读音 /bù qì/ 与 `bookcheck` /bʊktʃek/ 无法互相对应；「契」指向法律文书而非账目；且谐音「不起」在财务语境中为负面。

## 为什么中文名是「莱哲」而不是「账检」

`账检` 语义准确但**岗位错了**——它把中文名当成了产品说明书。本项目以 GitHub 为主场，英文名才是品牌资产，中文名只解决"念得顺、介绍得出"。故取纯音译：

`ledgerlint` /ˈlɛdʒər lɪnt/ → **莱**（le）+ **哲**（dʒer）+ **林**（lint）→ 简称「莱哲」

- 无实义、无谐音雷、念着不像会计软件（正是要的）
- 表意交给 slogan，不交给名字

被否候选：`莱哲林`（三字音译易读成人名）、`莱灵`（丢中间音节，且「洁灵」为日化品牌）、`雷哲林`（「雷」在口语中指踩雷）。
