## ① 关键判断：瓶颈已从「写代码」转移到「谁来看、谁来给真账」

**压缩后开发不再是关键路径，关键路径变成两段不可压缩的物理时间，这两段之间的空隙决定发布日期。**
第一段是 **G2 的真实流水等待窗（11/10–11/24，最短 2 周、长则 4 周）**，完全在主理人手上，agent 加速不了任何一次线下协调。第二段是 **12/12 之后的「规则修正 → 真实回归 → 会计盲评」串行环**：环的周期不由代码行数决定，而由「对方什么时候给代账报表 / 会计什么时候有空看 2 小时」决定，一轮 3–5 天，至少 3 轮。
因此本计划的组织原则是：**不依赖真实数据的部分（内核、输入解析、界面、断言框架、探针）全部在 11/10–12/11 压平做完；依赖真实数据的一切（规则内容、科目映射、勾稽口径、交付包排版）全部排到 G2 之后**。这是唯一能让两个物理窗口重叠的排法。
**代价要提前说清**：11/10–11/24 写的 12 类规则全部是「待校准草案」，11/28 的第一次真实流水校准必然推翻其中 3–5 类的科目选择。这部分返工已计入 §⑥ 返工储备，不藏在乐观工时里。

## ④ 释放时间的投向（本计划的核心主张）

压缩后首轮开发只需 **87 agent 小时**（≈11 人日等价），对照原 7 周 ×40h = 280 人时，释放约 **29 人日等价**。**不平均分配**，按「能否提高 A2-L2 与 A6」排序：

| 投向 | 原计划 | 释放后 | 量化目标 | 为什么排这个优先级 |
|---|---|---|---|---|
| **反向构造探针** | 5 人日（1/BLOCK） | **12 人日** | 5 条 BLOCK × 5 类错法（方向反 / 金额错 / 对象错 / 期间错 / 重复）= **25 个探针**，CI 全触发率 100% | A6 是唯一能证伪「断言全绿」的机制。1 个/BLOCK 只能证明「能报」，3 个以上才能证明「该报的都会报」 |
| **会计盲评轮次** | 0 | **4 人日** | 4 轮，每轮 1 名外部会计只看交付包 2h；目标：**第 3 轮起「看不懂的条目」= 0** | 这是唯一能解「零财务知识用户看不懂」的验证手段（交付总监 §3-1 点明这是 UI 硬仗） |
| **真实回归家数** | 1 家 | **5 人日** | **1 → 3 家**，各跑满 1 个月 | 第 2/3 家的作用是**证伪**规则，不是增加覆盖率。1 家永远可能是那家刚好符合规则的 |
| **事件类型扩张** | 12 类 | **3 人日** | **12 → 16 类**（上限 20 类） | 类数不是目标，是结果：以第 1 家的「未覆盖原因=无规则」清单归零为准。上限 20 是 15k 行预算倒推的 |
| **5 分钟上手实测** | 0 | **3 人日** | ≥5 名**非财务**人员（行政/设计/运营），**≥3 人 5 分钟内独立走到「生成交付包」**；失败者记录断点位置 | 冷启动纪律要求「自己装上、自己跑通」，不实测就是猜 |
| **返工储备 + S1/S2** | — | **2 人日** | 返工储备 4 人日（被 11/28、12/15、12/17 三次返工吃掉）+ S1 条款引用 1.5 人日 + S2 案例集 1 人日（见 §⑦） | 乐观工时不等于完成工时，储备必须显式存在；S1 必须在 T02 进契约，否则永远补不回来 |

### 为什么不建议「提前发布」

1. **发布窗口是一次性资产**。HelloGitHub / 少数派 / V2EX 的首帖转化只有一次；第二次触达同一批人是首次的 1/5。用 12/01 的未达标版本消耗掉它，等于把「12/28 一次性发布」变成「两次都不响」。
2. **12/01 与 12/28 的版本差不是代码，是「3 家真实账 + 4 轮盲评」**。A2-L2 发布线 ≥95%、首轮线 ≥90%，这 5 个百分点只能由真实回归挣来。提前发布就是把 BP2「断言绿但账错」的口径原样交给第一批用户——第三次重演同一个根因。
3. **提前发布没有承接能力**。试用开班需 G3 达标；用户第一周撞上「科目选错」，得到的不是 issue 而是「不好用」的口碑负债，开源项目的负口碑修正成本高于零口碑。
4. **唯一值得提前的形态已在计划内**：12/28 前对 3–5 家种子用户开 alpha（能看到 WARN 与局限、已签数据处理说明），不需要公开发布。**公开发布 = 承诺可承接；没承接能力就先别承诺。**

### 5.3 接口契约（TypeScript，编译期即规格）

```ts
// ── 1. 输入模型（B 产出 → C 消费）───────────────────────
export interface Transaction {
  readonly txnId: string;              // sha1(sourceHash + ':' + rowNo)，跨文件稳定
  readonly sourceHash: string;         // sources/*.csv 内容哈希，判「文件变没变」
  readonly rowNo: number;              // 原文件行号，所有报错都指向它
  readonly date: string;               // YYYY-MM-DD
  readonly direction: 'IN' | 'OUT';
  readonly amountCents: Cents;         // 正数；方向在 direction
  readonly balanceCents: Cents | null; // 缺失为 null，不许用 0 冒充
  readonly counterparty: string;
  readonly counterpartyAccount?: string;
  readonly summary: string;
  readonly serialNo?: string;
  readonly fingerprint: string;        // 幂等键：date|direction|amount|cp|summary
  readonly account: MoneyAccountCode;  // '1001' | '1002' | '1012'
}

// ── 2. 事件值域（C 全权；值域 T02 冻结，只允许追加）─────────
export type EventKey =
  | 'E1' | 'E2' | 'E4' | 'E5' | 'E6' | 'E7' | 'E8' | 'E11' | 'E12' | 'E13' | 'E16'
  | 'E99';  // 未识别：必须显形、禁止静默丢弃（A7 的兜底，不允许出现第二个兜底值）
// E1 收客户款(普票) E2 收客户款(专票) E4 收回应收 E5 付供应商(已收票) E6 赊购
// E7 付应付 E8 付费用 E11 股东投入 E12 预收/确认收入 E13 股东往来 E16 缴税

// ── 3. 规则命中（C 产出 → D 展示 / E 留痕）──────────────
export interface RuleHit {
  readonly ruleId: string;
  readonly ruleVersion: string;
  readonly event: EventKey;
  readonly confidence: 'HIGH' | 'LOW';
  readonly assumed: readonly string[];      // 「我猜的」必须在这里；空数组 = 没有猜
  readonly oneLiner: string;                // 一句人话，≤40 字
  readonly basis: readonly BasisRef[];      // 依据：规则行号 / 流水号 / 发票号 / 条款
  readonly questions?: readonly Question[]; // 三问，只对 top5 歧义事件
}
export type BasisRef =
  | { kind: 'RULE'; file: string; line: number }
  | { kind: 'TXN'; txnId: string; rowNo: number }
  | { kind: 'INVOICE'; invoiceNo: string }
  | { kind: 'CITE'; text: string; url?: string };  // ← 交付总监 S1，T02 一并冻结，不可事后追加

// ── 4. 落账模型（A 全权 → D/E 只读）─────────────────────
export interface JournalLine {
  readonly accountCode: string; readonly accountName: string;
  readonly direction: 'DEBIT' | 'CREDIT'; readonly amountCents: Cents;
  readonly counterparty?: string;   // 1122/2202 必填，对象级校验收这里
  readonly docNo?: string;
}
export interface PostedVoucher {
  readonly voucherId: string;
  readonly periodId: string;        // 由 voucherDate 派生，不许独立赋值
  readonly voucherNo: string; readonly voucherDate: string;
  readonly lines: readonly JournalLine[];
  readonly totalDebitCents: Cents; readonly totalCreditCents: Cents;
  readonly source: 'IMPORT' | 'MANUAL' | 'RECON' | 'REVERSE';
  readonly reverses?: string;       // 红冲指向原 voucherId
  readonly ruleSnapshot: Readonly<Record<string, string>>;
  readonly hit?: RuleHit;           // 依据链，进哈希
  readonly prevHash: string;        // 落账顺序的前一张，不是日期顺序
  readonly hash: string;
}

// ── 5. 断言（E 全权） · 6. 唯一写入口（A 独占，其他人只读）───
export type BlockId = 'B1' | 'B2' | 'B3' | 'B4' | 'B5';
export interface AssertionResult {
  readonly id: BlockId; readonly title: string;
  readonly passed: boolean;
  readonly skipped?: boolean;       // 「没查」不许写成「查过了」，汇总必须分列
  readonly severity: 'BLOCK'; readonly message?: string;
  readonly evidence?: Readonly<Record<string, number | string>>;
  readonly limitation: string;      // 编译期必填：这条查不出什么
}
export interface JournalPort {
  append(period: string, v: Omit<PostedVoucher, 'prevHash' | 'hash'>):
    Promise<{ voucherId: string; prevHash: string; hash: string }>;
  read(period: string): AsyncIterable<PostedVoucher>;
  readAll(): AsyncIterable<PostedVoucher>;
  verify(): Promise<{ ok: boolean; breakAt?: string }>;
```

### 5.4 契约先行：T01–T03 必须冻结的四个类型
